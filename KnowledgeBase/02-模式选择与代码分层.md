# 模块 02：模式选择与代码分层

## 概述
GDK 支持双业务模式：**纯 GF（GameHot）**与 **ET**。两者共用协议、配置和基础设施，通过编译宏互斥切换。

## Unity 业务分层
```text
Unity/Assets/Scripts/Game/
├── Procedure/        # GF 总入口流程，负责选择业务模式
├── Editor/           # 全局编辑器工具、构建、宏与 Toolbar
├── Generate/         # 非热更公共生成代码（不要手改）
├── ET/
│   ├── Loader/       # 稳定加载层与 GF 集成（不参与业务 DLL 热更）
│   ├── Editor/       # ET 编辑器工具（代码生成等）
│   └── Code/         # Model/Hotfix/ModelView/HotfixView 四程序集
└── Hot/
    ├── Loader/       # 稳定加载层
    └── Code/         # Game.Hot.Code 热更新业务程序集
```

## 目录选择指南
| 需求 | 推荐位置 |
| --- | --- |
| GF 公共启动或基础能力 | `Game/` 对应模块 |
| GameHot 可热更业务 | `Game/Hot/Code/` |
| GameHot 稳定加载桥接 | `Game/Hot/Loader/` |
| ET 无视图 Entity 数据 | `Game/ET/Code/Model/` |
| ET 无视图 System 逻辑 | `Game/ET/Code/Hotfix/` |
| ET 客户端 View/Mono | `Game/ET/Code/ModelView/` |
| ET 客户端 View System | `Game/ET/Code/HotfixView/` |
| ET 与 GF 的适配层 | `Game/ET/Loader/UGF/` |
| 自动生成代码 | 对应 `Generate/`，不要手改 |

## ET 程序集边界
| 程序集 | 内容 | 是否含 Unity 视图 |
| --- | --- | --- |
| `Game.ET.Code.Model` | 共享/纯逻辑数据 | 否 |
| `Game.ET.Code.Hotfix` | 业务 System 与热更逻辑 | 否 |
| `Game.ET.Code.ModelView` | 客户端视图模型与 Mono 绑定 | 是 |
| `Game.ET.Code.HotfixView` | 客户端视图 System | 是 |

依赖链：Model → Hotfix → ModelView → HotfixView。`CodeMode` 由 `UNITY_ET_CODEMODE_CLIENT / SERVER / CLIENTSERVER` 三个互斥符号控制。

## 模式切换工具（Game/Define Symbol）
执行 `Game/Define Symbol/Refresh`（`Editor/DefineSymbol/DefineSymbolTool.cs`）会：
1. 增删 Scripting Define Symbol（`UNITY_ET` / `UNITY_GAMEHOT` / `UNITY_HOTFIX`）。
2. 切换 ET 或 GameHot 的 `luban.conf.active`。
3. 激活对应 Resource Rule 配置（`ResourceRuleTool.ActivateRule_ET/GameHot`）。
4. 更新 `link.xml` 条件区块（`LinkXMLHelper`）。
5. 更新 HybridCLR 热更程序集与 AOT 程序集列表。
6. 清理旧的临时 DLL 构建目录。

> 手工改宏不会同步关联配置，必须走菜单；切换后等待 Unity 编译再重新导表。

## 热更新开关（UNITY_HOTFIX）
- **未启用**：业务程序集由 Unity 编译随 Player 发布，CodeRunner 从当前 AppDomain 查找入口，调试最直接。
- **启用**：ET/GameHot 编译工具把业务程序集复制为 `.dll.bytes` + `.pdb.bytes` 资源；Loader 从 GF Resource 加载字节，`Assembly.Load` 启动业务入口。HybridCLR 同时维护热更程序集列表与 AOT 补充元数据。
