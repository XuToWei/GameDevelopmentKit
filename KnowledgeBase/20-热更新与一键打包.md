# 模块 20：HybridCLR 热更新与一键打包

## 概述
GDK 用 **HybridCLR** 管理热更程序集、AOT 元数据与构建流程；用**一键打包工具**（`Game/Editor/Build/`）产出资源、安装包并支持本地资源服务器。服务端/工具链的 Linux 发布由 `Publish-linux-x64.ps1` 完成。

## HybridCLR 热更新
### 基本概念
- 未启用 `UNITY_HOTFIX`：业务代码随 Player 编译，调试最直接。
- 启用 `UNITY_HOTFIX`：ET/GameHot 编译工具把业务程序集复制为 `.dll.bytes` + `.pdb.bytes` 资源；Loader 从 GF Resource 加载字节后 `Assembly.Load`。
- HybridCLR 同时维护：热更新程序集列表、AOT 补充元数据（AOT dll 列表）、`link.xml` 裁剪配置。

### 完整流程（`Book/HybridCLR热更.md`）
1. 用 Unity 菜单打开 HybridCLR 面板，安装/更新 HybridCLR 包。
2. `HybridCLR/Generate/All`：生成 AOT 补充元数据、link.xml、热更程序集列表。
3. 切换 `UNITY_HOTFIX` 宏（Define Symbol 工具自动同步 HybridCLR 设置）。
4. 用热更工具构建 DLL 字节资源（`dll.bytes`）。
5. 打资源包（含 `dll.bytes`），发布到资源服务器/CDN。
6. 客户端启动流程自动检测版本并下载热更资源。

### 关键点
- `Code/` 程序集进入 HybridCLR 热更；`Loader/` 为稳定加载层，**不参与**业务 DLL 热更新。
- 热更元数据（`AOTGenericReferences` 等）由 HybridCLR 生成器自动维护。
- 模式切换工具会同步更新 HybridCLR 程序集列表并 `RefreshSettings`（见模块 02）。

## 一键打包（Game/Build Tool Editor）
### 入口与核心
- 窗口：`Game/Build Tool Editor`（`BuildToolEditor.cs`）。
- 核心方法：`BuildHelper.BuildPkg`。

### BuildPkg 流程
```
BuildHelper.BuildPkg
 ├─ 切换目标平台
 ├─ 清空 Temp/Pkg/<Platform>
 ├─ BuildResource（资源打包 → Temp/Bundle，版本信息 → Temp/Version）
 └─ 仅用 Assets/Launcher.unity 调 BuildPipeline.BuildPlayer
      → 产物 Temp/Pkg/<Platform>/<productName>.exe/.apk
```

### 支持平台
Windows / Windows64 / Android / iOS / macOS / Linux / WebGL。

### 其他按钮
- 仅建资源（跳过 Player 构建）。
- 刷新 Windows64 StreamingAssets。
- Open Pkg Folder（打开产物目录）。
- Build Kit.sln（编译 .NET 工具/服务端）。

### 资源模式
- 模式读取 `GameEntry.prefab` 的 `m_ResourceMode`（包内/文件系统/Web 等）。

## Linux 发布（Publish-linux-x64.ps1）
```powershell
# 对仓库执行
dotnet publish -r linux-x64 --no-self-contained -c Release
# 将 Bin/linux-x64/publish 复制为 Publish/linux-x64/Bin
# 将根 Config/ 复制为 Publish/linux-x64/Config
```
- 产出服务端/工具链的 Linux 可运行包（含 Config 数据）。
