# 模块 16：ET 动态事件

## 概述
ET 动态事件是 GDK 在 ET 框架上的扩展：**按实体类型 + SceneType 广播事件**，解决"某类实体都收到通知"的广播需求，替代逐实体手动遍历。代码位于 `Game/ET/Code/Model/Share/Module/DynamicEvent/`。

## 核心类
| 类 | 职责 |
| --- | --- |
| `DynamicEventComponent` | 挂 Scene，事件表容器 |
| `DynamicEventTypeSystem` | 扫描 `[DynamicEvent(SceneType)]` 标记，注册事件表 |
| `DynamicEventReceiverComponent` | 实体挂载后成为事件接收者 |
| `ADynamicEvent` | 事件基类（泛型：事件参数类型） |

## 事件定义
```csharp
// 定义事件：参数类型为 HpChangeArgs，作用于 Unit 类型实体
[DynamicEvent(SceneType.Client)]
public class UnitHpChangeEvent : ADynamicEvent<Unit, HpChangeArgs>
{
    protected override void Handle(Unit entity, HpChangeArgs args)
    {
        // 处理逻辑（实体收到事件）
    }
}
```

## 广播流程
```
Publish<A>(sceneType, args)
 └─ 按参数类型 A 查事件表
     └─ sceneType.HasSameFlag 过滤（SceneType 位标记匹配）
         └─ 按事件声明的实体类型查 RegisteredEntityDict
             └─ 逐实体执行 Handle(entity, args)
```

## 关键 API
```csharp
// 发布：向指定 SceneType 下的 Unit 实体广播
scene.GetComponent<DynamicEventComponent>()
    .Publish<UnitHpChangeArgs>(SceneType.Client, args);

// 实体侧：挂接收组件即自动订阅
entity.AddComponent<DynamicEventReceiverComponent>();
```

## 设计要点
- **双过滤**：先按 SceneType（位标记 `HasSameFlag`）过滤场景，再按实体类型过滤接收者，精准广播。
- 事件类用特性 `[DynamicEvent(SceneType)]` 声明作用域，`DynamicEventTypeSystem` 启动时一次性扫描注册，运行时查表零反射。
- 与 GF 全局事件（模块 11）的区别：动态事件面向 ET 实体集合广播，天然携带实体上下文。
- 无实体匹配时不产生任何调用开销；实体销毁自动从接收表移除。
